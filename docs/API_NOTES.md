## Observations

- **leaderboard:** GET https://stats-data.hyperliquid.xyz/Mainnet/leaderboard → 200, 39.1 MB, 47152 rows. Windows: ['allTime', 'day', 'month', 'week'].
- **leaderboard:** Fixture keeps only the first 60 rows (full payload is too large to commit).
- **meta:** Undocumented-in-spec fields present: `marginTableId`, `onlyIsolated`, `marginMode`, `isDelisted`, top-level `marginTables` (tiered max leverage by notional) and `collateralToken`. Liquidation maths must use margin tiers.
- **metaAndAssetCtxs:** Response is a 2-element array `[meta, [assetCtx…]]`, ctxs index-aligned with `meta.universe`. `funding` is the current hourly rate. `midPx` is null for 56 (illiquid/delisted) assets — use markPx then.
- **allMids:** Keys include spot (`@<n>`, `PURR/USDC`) and other markets (`#<n>`) besides perp coin names. Always filter to `meta.universe` names.
- **subAccounts:** **Leaderboard rows aggregate a master wallet and its sub-accounts.** For the top-volume row the master holds 14544 USD and 0 positions while 50 sub-accounts hold 33967701 USD. Copying the master address would copy nothing. `subAccounts` returns null when there are none.
- **fills pagination:** Very active wallet, 90d window: page sizes [2000, 2000, 2000, 2000, 2000, 2000] (stopped at 6), 11978 unique fills, oldest available fill only 1.1 days ago, costing 720 weight. Asking for an older startTime silently starts at the oldest *available* fill — there is no error or flag for truncated history.
- **fills pagination:** Paginating by setting startTime = last page's max `time` re-returns boundary fills (22 duplicates here) — de-duplicate by `tid`.
- **fills pagination:** Docs claim a 10,000-fill history cap; a manual run on 2026-10-02 paginated ~39,000 fills (≈3.8 days) for one sub-account, so the real cap is larger or time-based. Treat history depth as unknown and detect it.

## Manual notes (kept across probe runs)

### Rate limits (from docs, 2026-10-02)
- Per-IP REST budget: **1200 weight / minute**.
- Weight 2: `l2Book`, `allMids`, `clearinghouseState`, `orderStatus`, `spotClearinghouseState`,
  `exchangeStatus`.
- Weight 60: `userRole`.
- Weight 20: every other info request (`meta`, `metaAndAssetCtxs`, `portfolio`,
  `userFillsByTime`, `fundingHistory`, …).
- `userFills`, `userFillsByTime`, `fundingHistory`: additional weight per 20 items returned
  (we charge +1 per 20 items).
- The bot's token bucket runs at 50% (600/min) because Actions runners share IPs.

### Fills
- `userFillsByTime` returns at most **2000** fills per response and only the **10000 most recent**
  fills of a user are queryable.
- Fill fields beyond the spec: `feeToken`, `twapId` (nullable), `builderFee` (only when non-zero).

### Portfolio
- No 90-day window exists. Windows: day/week/month/allTime + perp* variants. `month` ≈ 30 days
  at a few-hour resolution; `allTime` covers the account's whole life at coarse resolution
  (tens of points). 90-day drawdown must come from `allTime` (coarse) or be reconstructed.
